# Fase 3.5 — Timestamp Timezone-Aware (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Semua timestamp Coffee Ledger disimpan sebagai UTC timezone-aware dan ditampilkan
dalam `Asia/Jakarta`, sebelum Next.js mulai menulis ke Neon DB yang sama.

**Architecture:** Ubah `default_factory` kedua model jadi `datetime.now(UTC)` dan kolomnya
jadi `DateTime(timezone=True)`, lalu ALTER kolom Neon dari `timestamp` ke `timestamptz`.
Konversi ke waktu Jakarta terjadi hanya di lapisan tampilan (`app/app.py`), tidak pernah di
service atau repository.

**Tech Stack:** Python 3.12, SQLModel/SQLAlchemy, psycopg2, Neon Postgres, pytest.

### Task 1: Timestamp UTC timezone-aware di model

**Files:**
- Create: `tests/test_timezone.py`
- Modify: `src/coffee_ledger/models.py:7,10,37,46`

**Kenapa assertion-nya bukan setelah round-trip DB.** Diverifikasi 2026-09-03: SQLite
membuang `tzinfo` walaupun kolomnya `DateTime(timezone=True)` — nilai UTC-nya benar, tapi
kembali sebagai naive. Test suite jalan di SQLite; produksi di Postgres. Jadi assertion
round-trip akan MERAH walaupun kodenya benar. Yang dijamin di sini: kode kita tidak pernah
lagi menghasilkan waktu naive.

- [x] **Step 1: Tulis test yang gagal**

Buat `tests/test_timezone.py`:

```python
"""Timestamp selalu UTC timezone-aware.

Assertion-nya pada objek hasil `default_factory`, BUKAN setelah round-trip DB:
SQLite (dipakai test) membuang tzinfo walau kolomnya DateTime(timezone=True),
sementara Postgres (produksi) menyimpannya utuh. Yang dijamin di sini adalah
kode kita, bukan perilaku backend.
"""

from datetime import UTC, date, datetime, timedelta

from coffee_ledger.models import Lot, Transaction, TxnKind, TxnReason


def test_transaction_ts_is_utc_aware():
    txn = Transaction(lot_id=1, kind=TxnKind.IN, reason=TxnReason.ACQUIRE, grams=100)

    assert txn.ts.tzinfo is not None
    assert txn.ts.utcoffset() == timedelta(0)


def test_lot_created_at_is_utc_aware():
    lot = Lot(name="Gayo", origin="Aceh", varietal="RB", roast_date=date(2026, 6, 20))

    assert lot.created_at.tzinfo is not None
    assert lot.created_at.utcoffset() == timedelta(0)


def test_ts_default_is_close_to_now():
    """Jaga-jaga default_factory gak ketuker jadi konstanta."""
    txn = Transaction(lot_id=1, kind=TxnKind.IN, reason=TxnReason.ACQUIRE, grams=100)

    assert abs(txn.ts - datetime.now(UTC)) < timedelta(seconds=5)
```

### Task 2: Tampilkan waktu dalam Asia/Jakarta

**Files:**
- Modify: `app/app.py:7-13,188`

Aturan dari spec §9: simpan UTC, tampilkan `Asia/Jakarta`, konversi hanya di lapisan
tampilan. Helper harus menangani dua bentuk masukan karena backend berbeda perilaku —
Postgres mengembalikan aware, SQLite naive (bernilai UTC).

**Catatan pilihan sadar:** helper ini tidak diberi unit test sendiri. Menaruhnya di modul
terpisah semata agar bisa di-import test berarti menambah modul untuk menguji tiga baris
stdlib; `tests/test_app.py` sudah memastikan app-nya render tanpa exception. Kalau nanti
logika tampilan tumbuh, barulah diekstrak.

- [x] **Step 1: Tambah helper**

Di `app/app.py`, ganti blok import baris 7–13:

```python
import sys
from datetime import UTC, date, datetime
from pathlib import Path
from zoneinfo import ZoneInfo

import altair as alt
import pandas as pd
import streamlit as st
```

Tambahkan tepat setelah definisi `_db_url()` (yang berakhir dengan `return None`):

```python
WIB = ZoneInfo("Asia/Jakarta")


def _to_wib(ts: datetime) -> datetime:
    """UTC → waktu Jakarta. Postgres balikin aware, SQLite naive — samain dulu."""
    if ts.tzinfo is None:
        ts = ts.replace(tzinfo=UTC)
    return ts.astimezone(WIB)
```

- [x] **Step 2: Pakai helper di tabel riwayat**

Di `app/app.py`, di dalam pembangunan DataFrame riwayat (tab 🧾 Riwayat), cari baris
`"Waktu": t.ts,` dan ganti jadi:

### Task 3: Periksa data yang sudah ada di Neon

**Files:** tidak ada perubahan file — ini langkah investigasi.

Menentukan apakah klausa `USING ts AT TIME ZONE 'UTC'` di Task 4 aman. Klausa itu menyatakan
"semua nilai naive yang ada selama ini UTC". Kalau ada baris yang ditulis dari mesin WIB,
pernyataan itu salah dan baris tersebut akan meleset 7 jam.

**Dugaan awal, masih harus dibuktikan:** `_db_url()` (`app/app.py:29`) hanya membaca
`st.secrets["DATABASE_URL"]`. Secara lokal `.streamlit/secrets.toml` tidak ada (gitignored,
dan `.example`-nya bilang lokal tidak perlu), jadi `make_engine` jatuh ke default SQLite.
Artinya baris di Neon semestinya semuanya berasal dari Streamlit Cloud alias UTC. Task ini
menguji dugaan itu.

- [ ] **Step 1: Siapkan connection string**

Ambil dari Streamlit Cloud → Settings → Secrets, lalu di shell:

```bash
export NEON_URL='postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require'
```

Jangan ditulis ke file mana pun di repo.

- [ ] **Step 2: Jalankan query pemeriksaan**

```bash
uv run python - <<'PY'
import os
from sqlalchemy import create_engine, text

e = create_engine(os.environ["NEON_URL"])
with e.connect() as c:
    print("TimeZone:", c.execute(text("SHOW TimeZone")).scalar())
    print("now UTC :", c.execute(text("SELECT now() AT TIME ZONE 'UTC'")).scalar())
    for tbl, col in (("transaction", "ts"), ("lot", "created_at")):
        row = c.execute(text(f"""
            SELECT count(*) AS n,
                   min({col}) AS earliest,
                   max({col}) AS latest,
                   count(*) FILTER (WHERE {col} > now() AT TIME ZONE 'UTC') AS in_future
            FROM "{tbl}"
        """)).mappings().one()
        print(f"{tbl}.{col}:", dict(row))
PY
```

- [ ] **Step 3: Tafsirkan hasilnya**

Tiga hal yang dicari:

1. **`in_future` harus 0.** Baris yang ditulis dengan jam WIB tapi disimpan naive akan
   bernilai 7 jam di depan UTC sebenarnya. Kalau `in_future > 0`, ada kontaminasi WIB dan
   Task 4 **tidak boleh dijalankan apa adanya** — hentikan, laporkan berapa barisnya.
2. **`TimeZone` harus `UTC`.** Ini yang bikin urutan ALTER-vs-deploy tidak kritis. Kalau
   bukan UTC, tambahkan `SET TIME ZONE 'UTC';` di awal transaksi Task 4.
3. **`earliest`/`latest` masuk akal** dibanding ingatanmu kapan app ini dipakai. Kalau
   `latest` meleset ~7 jam dari kapan kamu terakhir mencatat, itu justru bukti bahwa yang
   tersimpan memang UTC dan tafsir kita benar.

Catat hasilnya untuk dilampirkan di commit message Task 4.

### Task 4: ALTER kolom Neon ke timestamptz

**Files:** tidak ada perubahan file — migrasi manual ke DB produksi.

`SQLModel.metadata.create_all()` hanya membuat tabel yang belum ada dan **tidak pernah
meng-ALTER tabel yang sudah ada**. Tanpa langkah ini, kolomnya selamanya
`timestamp without time zone` sekalipun modelnya sudah benar — dan `drizzle-kit introspect`
di Fase 4b akan menyalin tipe yang salah itu ke TypeScript.

**Prasyarat:** Task 3 selesai dan `in_future = 0` di kedua tabel.

**Keputusan: tidak memakai `server_default=now()`.** Diangkat saat review kode Task 1.
Kedua penulis — `default_factory` di Python, dan nanti Drizzle — mengisi kolom ini secara
eksplisit, jadi default di sisi server tidak akan pernah menyala; ia hanya menolong kalau
ada INSERT manual yang menghilangkan kolomnya, dan itu belum ada. Menambahkannya berarti
konfigurasi yang tidak pernah dieksekusi tapi tetap harus dipahami orang berikutnya.

Kalau nanti berubah pikiran, biayanya kecil: tambahkan `ALTER COLUMN ... SET DEFAULT now()`
dan jalankan ulang `drizzle-kit introspect` — satu perintah, bukan menulis ulang Fase 4b.

- [ ] **Step 1: Jalankan migrasi**

```bash
uv run python - <<'PY'
import os
from sqlalchemy import create_engine, text

e = create_engine(os.environ["NEON_URL"])
with e.begin() as c:                      # DDL Postgres transaksional — batal utuh kalau gagal
    c.execute(text("SET TIME ZONE 'UTC'"))
    c.execute(text('ALTER TABLE "transaction" ALTER COLUMN ts '
                   "TYPE timestamptz USING ts AT TIME ZONE 'UTC'"))
    c.execute(text('ALTER TABLE lot ALTER COLUMN created_at '
                   "TYPE timestamptz USING created_at AT TIME ZONE 'UTC'"))
print("migrated")
PY
```
